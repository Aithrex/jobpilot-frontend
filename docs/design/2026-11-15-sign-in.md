# Sign-in redesign (2026-11-15)

`/login`, `/register`, `/reset-password` and `/oauth/callback` were rebuilt on
the public design system from
[`2026-11-15-home-redesign.md`](2026-11-15-home-redesign.md). The backend
contract is `docs/specs/sign-in.md` in `jobpilot-backend`. The code is the
source of truth; if this note and the code disagree, fix the note.

## What it is

One screen that starts with the email address. `/login` and `/register` render
the same component (`components/auth/SignInFlow.tsx`) with different words.

| Step | When | What is on it |
|---|---|---|
| Address | always first | Google above, the email field, Continue |
| Password | the address has an account with a password | password, Sign in, "Email me a code instead", Forgot password |
| Provider or code | the account has no password | "Continue with Google" if linked, "Email me a code" |
| New account | no account for the address | age and Terms box, "Email me a code", optional password |
| Code | a code was mailed | six boxes, resend with a countdown, "Use a different email" |

Because the address comes first, whichever page someone lands on, an existing
account is signed in and a new address is offered an account. "Email already
registered" is no longer a dead end on sign-up.

## Decisions

- **Public system, no second palette.** `usePublicSurface`, `pub-h2/h3/h4`,
  `pub-btn`, the navy `pub-brand-band`. The few classes sign-in needed (field,
  code boxes, notice, identity row) are in `components/auth/auth.css` and name
  no colour.
- **The navy chapter is the desktop side panel.** It replaces the old hero
  illustration (`landing/story/`, deleted). Three lines the product does
  today, in the home page's words. Not shown below `lg`.
- **Buttons at the public height (52px), fields to match, 16px text** so a
  phone does not zoom on focus.
- **Errors say what to do next.** A wrong code says how many tries are left.
  An expired code turns the main button into "Send a new code". A wait shows
  the time and counts down. A provider failure stays on screen until the
  person acts (it used to redirect after two seconds).
- **A new account needs no password.** A code proves the address either way,
  so the password is an option, not a step.
- **The step lives in router state.** Back walks the steps. The password and
  the code stay in memory only; arriving on the code step without them (a
  reload) returns to the address step with the address kept.
- **A provider button is a navigation** to
  `/api/auth/oauth/<provider>/authorize?redirect=1`, never a fetch: the backend
  sets the cookie that ties the flow to this browser.
- **Only providers the backend lists are drawn.** Microsoft and Apple appear
  by themselves once the backend is configured for them.
